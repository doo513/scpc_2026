  ## 단계별 구현 계획

  ### Stage 0 — 공식 기준선·scorer·artifact provenance

  - 변경 축: 평가 및 artifact provenance만 변경하며 inference는 건드리지 않는다.
  - 입력/출력: 공식 ZIP·current source → canonical score/report/manifest.
  - owner: generate_reports.py와 build_manifest.py.
  - 작업: 공식 notebook scorer parity를 복원하고 중복 artifact writer와 stale report를 정
    리한다.

  - 테스트: 격리 재실행 byte parity, 공식 scorer 0.8186, submission hash, source/data/
    scorer hash 검증.

  - Gate: scorer parity와 단일 artifact owner가 모두 통과해야 한다.
  - Rollback: tooling 변경만 되돌리고 production answer는 유지한다.
  - 비용: MEDIUM

  ### Stage 1 — Ontology·authoritative ownership

  - 변경 축: 의미 타입과 최종 owner.
  - 입력/출력: current ontology와 중복 legacy 타입 → owner가 하나인 canonical ontology.
  - owner: core.ontology, 수정된 ownership registry.
  - 작업: domain, operation, target, disclosure, reason code의 legacy/shadow 중복을 제거할
    migration mapping을 확정한다.

  - 테스트: enum/reference integrity, 불가능한 조합, UNKNOWN default 금지.
  - Gate: shadow trace와 current production output이 동일해야 한다.
  - 비용: MEDIUM

  ### Stage 2 — Typed Fact·RecordAdapter

  - 변경 축: raw input 해석.
  - 입력/출력: TaskView → TypedFactSnapshot.
  - owner: RecordAdapterRegistry, object/capability/session adapters.
  - 작업: 현재 production-active typed fact 경로를 재사용하고
    chronology·missing·unknown·conflict 계약을 고정한다.

  - 테스트: object/record permutation, duplicate conflict, invalid/missing, raw-access AST
    검사.

  - Gate: RecordAdapter 외부 raw record 해석 0건.
  - 비용: MEDIUM

  ### Stage 3 — Parser·Context Binder·FixedSLM 승격 결정

  - 변경 축: 자연어와 SLM evidence authority.
  - 입력/출력: SurfaceParse + TypedFacts → ContextBindingResult → Pre-SLM Candidate
    Evidence.

  - owner: parser는 deterministic evidence, FixedSLM adapter는 proposal evidence, Context
    Binder는 scope-aware authority를 소유한다.

  - 현재 결정: KEEP_SHADOW. 승격 전 production 영향은 0건이다.

  #### FixedSLM 공식 계약

  공식 baseline에서 확인된 interface만 사용한다.

  class FixedSLMClient
  model_id = "scpc-final-fixed-slm-local-facade"
  summarize_task(task: dict) -> dict

  허용 출력:

  risk_flags: list[str]
  requires_redaction: bool
  requires_confirmation: bool
  audit_tags: list[str]

  추가 필드나 FinalDecision 출력은 허용하지 않는다. 공식 timeout·failure 계약은 없으므로
  실패 시 proposal을 폐기하고 parser-only 평가를 그대로 사용한다.

  #### 승격 판정

  Stage 3 종료 시 report에 정확히 하나만 기록한다.

  PROMOTE

  - 공식 interface와 위 출력 schema 검증 완료.
  - 고정된 held-out paraphrase·ambiguity suite에서 parser-only보다 추가 통과 사례가 최소 1
    건 존재하고 회귀는 0건.

  - 공식 dev overall·필수 축·exact count가 parser-only보다 악화되지 않음.
  - quotation·negation·correction·name/ID substitution metamorphic 검증 통과.
  - hard fact·current direct evidence·active constraint authority 침해 0건.
  - timeout·exception·invalid type·unknown field에서 parser-only answer와 byte-equivalent
    하게 복구.

  - SLM proposal이 직접 disposition, target, control, policy 또는 plan을 생성한 사례 0건.

  KEEP_SHADOW

  - interface와 schema는 검증 가능하지만 일반화 개선이 확인되지 않음.
  - 또는 공식 dev·metamorphic 회귀나 authority 위반이 하나라도 존재함.
  - 이 경우 해당 release line에서는 shadow diagnostic으로만 유지하고 production candidate
    set에는 병합하지 않는다.

  REMOVE

  - 공식 interface를 실행할 수 없거나 output schema를 안정적으로 검증할 수 없음.
  - parser-only 복구를 보장할 수 없음.
  - 이 경우 adapter와 runtime dependency를 제거하고 contract 감사 기록만 보존한다.

  #### Stage 3 산출물과 gate

  Stage report에는 다음을 기록한다.

  fixed_slm_status
  interface/source hash
  schema validation 결과
  parser-only 대비 diff
  official dev diff
  paraphrase·metamorphic 결과

  - KEEP_SHADOW·REMOVE도 명시적으로 완료된 결정이며 미결정 상태로 취급하지 않는다.
  - status가 없거나 증거 hash가 stale이면 Stage 4 진입을 금지한다.
  - 비용: HIGH

  ### Stage 4 — Candidate·RulePack·BaseBlueprint

  - 변경 축: domain-operation 후보 의미.
  - 입력:
      - PROMOTE: parser evidence + validated low-authority SLMEvidence.
      - KEEP_SHADOW 또는 REMOVE: parser evidence only.

  - 출력: exact RulePackKey, role/information spec, base blueprint가 연결된 candidate set.
  - owner: CandidateSetBuilder, RulePackRegistry.
  - 작업: shadow rulepack/evaluator를 production 후보 경로에 연결하되 legacy 선택은 아직
    유지한다.

  - 테스트: unsupported key, role mismatch, missing slot, candidate collision, sparse
    generation, task-specific key 부재.

  - Gate: FixedSLM status와 다른 입력 경로가 사용되면 실패한다.
  - 비용: HIGH

  ### Stage 5 — ConstraintEffect·FinalPlanRequirements·Capability

  - 변경 축: 후보별 실행 가능성.
  - 입력/출력: global/pair constraint → effect algebra → final requirements → capability
    assessment.

  - owner: constraint registries, effect algebra, plan requirement composer.
  - 작업: legacy constraint/blueprint 의미를 canonical shadow 구현으로 이전한다.
  - 테스트: permutation, idempotence, effect conflict, target-scoped consent, capability
    ablation, terminal 보존.

  - Gate: hard restriction 해제나 compiler 재판단 0건.
  - 비용: HIGH

  ### Stage 6 — CandidateDisposition·AuthorizedFallback

  - 변경 축: 후보 상태와 fallback 선택.
  - owner: CandidateDispositionPolicy, AuthorizedFallbackSolver.
  - 작업: hard compatibility를 통과한 후보에만 ranking을 적용하고 fallback destination을
    같은 evaluator로 재평가한다.

  - 테스트: missing/block/conflict 조합, unauthorized fallback, cycle/self-loop,
    correction-vs-fallback.

  - Gate: generic user target이나 차순위 자동 실행 0건.
  - 비용: HIGH

  ### Stage 7 — DecisionBundle·Projection

  - 변경 축: 결정 잠금과 output 의미 분리.
  - 입력/출력: candidate result → SubDecisionIR → DecisionBundle → Projection DTO.
  - owner: DecisionBundle 및 Projection Builder.
  - 작업: execution target과 response target을 분리하고 compiler에 필요한 의미를
    projection에 완전하게 담는다.

  - 테스트: lock digest, projection losslessness, deterministic output, mutation
    rejection.

  - Gate: 공식 aggregate 규칙이 없는 multi-operation은 production 전환하지 않는다.
  - 비용: HIGH

  ### Stage 8 — Session Overlay·Atomic Commit

  - 변경 축: session/memory side-effect 시점.
  - 입력/출력: provisional writes → validation result → commit eligibility → atomic
    commit.

  - owner: SpeculativeSessionOverlay, AtomicCommitCoordinator.
  - 작업: current 직접 mutation을 overlay write로 교체한다.
  - 테스트: validation failure, atomic failure, dependency rollback, independent
    operation, stale validation, commit=False.

  - Gate: validation 이전 persistent mutation 0건.
  - 비용: HIGH

  ### Stage 9 — Pure Compiler·종단 Validator

  - 변경 축: public answer materialization.
  - 입력/출력: immutable projection → schema-valid answer → validation result.
  - owner: projection compilers와 consistency validator.
  - 작업: shadow compiler를 production에 연결하고 validator를 commit 이전으로 이동한다.
  - FixedSLM 검증:
      - PROMOTE이면 compiled output이 parser/hard-fact authority를 침해하지 않았음을
        lineage로 재검증한다.

      - 다른 상태에서는 SLM-derived provenance가 production answer에 존재하면 실패한다.

  - 테스트: raw task 접근 금지, 호출 순서 독립, 동일 projection 동일 output, unavailable
    action, rollback terminal 부재.

  - Gate: compiler isolation·authority preservation·validation-before-commit 모두 통과.
  - 비용: HIGH

  ### Stage 10 — Vertical slice·전체 release

  - 변경 축: runtime routing.
  - 작업: contract-confirmed single-operation 사례부터 new path로 전환하고 full dev/
    screening shadow diff를 기록한다.

  - FixedSLM release 조건:
      - status가 정확히 PROMOTE, KEEP_SHADOW, REMOVE 중 하나.
      - Stage 3 report와 source/test hash가 current.
      - PROMOTE이면 모든 승격 조건을 재검증.
      - 다른 상태이면 production influence가 0건임을 재검증.

  - 전체 release gate:
      - 공식 scorer parity.
      - configured dev overall ≥0.9421, 축별 floor, non-exact ≤10.
      - 전체 테스트 통과.
      - artifact content/source/scorer/FixedSLM hash freshness.
      - production owner 중복 0건.

  - Rollback: gate 실패 시 routing만 legacy로 복귀한다.
  - 삭제: full switch 후에만 legacy evaluator, constraint, blueprint, compiler, session
    path를 제거한다.

  - 비용: HIGH
