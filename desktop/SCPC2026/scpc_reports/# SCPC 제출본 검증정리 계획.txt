 # SCPC 제출본 검증/정리 계획

  ## Summary

  최종 제출 후보는 scpc_parser/submission.csv로 유지한다. Downloads의 두 CSV는 byte-identical 구버전이므로 제출 후보에서 제외하고, 검증 스크립트와 runner
  를 더 엄격하게 고친 뒤 새 CSV를 재생성한다.

  ## Key Changes

  - validate_submission.py
      - 기본 검증 대상 경로를 Path.cwd()/submission.csv가 아니라 스크립트 폴더 기준 Path(__file__).resolve().parent / "submission.csv"로 변경한다.
      - 인자를 주면 명시 경로를 검증하고, 인자가 없으면 항상 scpc_parser/submission.csv를 검증한다.

  - run_submission.py
      - submission_schema.json을 못 찾으면 즉시 FileNotFoundError를 발생시킨다.
      - schema가 있을 때만 검증하는 선택식 로직을 제거하고, jsonschema.validate(instance=payload, schema=schema)를 필수 단계로 만든다.
      - 검증 통과 후에만 submission.csv를 쓴다.

  - 제출 파일 정리
      - python3 run_submission.py로 scpc_parser/submission.csv를 재생성한다.
      - 필요하면 검증 완료된 scpc_parser/submission.csv를 /mnt/c/Users/doo33/Downloads/submission.csv로 복사하고, submission_recommended_consistent.csv도
        같은 검증본으로 맞춘다.

  ## Test Plan
  - python3 run_submission.py
      - schema 미발견 시 실패해야 한다.
      - 출력에 아래 3줄이 포함되어야 한다:
          - official schema validation passed
          - schema: scpc.final.answer.v1
          - answers: 700

  - CSV 구조 확인:
      - row 수 2
      - header ['submission']
      - data row column 수 1
      - answer key가 정확히 content_scope, control, focal_id, plan_events, policy, target 6개뿐이어야 한다.

  - 비교 확인:
      - Downloads의 기존 두 파일은 구버전이므로 사용하지 않는다.
      - 최종 복사 후에는 Downloads 제출 파일과 scpc_parser/submission.csv의 SHA256이 같아야 한다.

  ## Assumptions

  - 제출 대상은 현재 record 기반으로 재생성된 scpc_parser/submission.csv이다.
  - Downloads의 현재 두 CSV는 이전 extra-field 버전이므로 폐기 또는 덮어쓰기 대상이다.
  - jsonschema는 현재 환경에 설치되어 있으므로 추가 설치 없이 검증 가능하다.
